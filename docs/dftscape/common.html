dftscape.common

Common utilities and base classes for DFTScape molecular landscape exploration.

This package provides the foundational components and utilities used throughout the DFTScape system for molecular structure analysis and landscape exploration. It contains reusable patterns, data structures, and algorithms that support the core functionality of DFTScape's molecular exploration capabilities.

Key Components:

Data Structures (data_structures.py): SerialisableDataClass: Base class for dataclasses with automatic JSON serialization support. Provides to_config()/from_config() methods for converting complex nested objects to/from dictionaries, with special handling for numpy arrays and nested serializable objects.

Registry Pattern (registry.py): BaseRegistry: Generic base class implementing the registry pattern for pluggable components. Supports decorator-based registration and dynamic instantiation of components by name. Used for extensible architectures throughout DFTScape.

Distance Functions (distance.py): DistanceRegistry: Registry for molecular structure distance functions DistanceFunction: Protocol defining the interface for distance functions RMSDDistance: Root Mean Square Deviation distance with multiple methods EuclideanDistance: Simple Euclidean distance between coordinate arrays MaxCoordinateDistance: Maximum coordinate distance between atoms

Usage Examples:

Basic Data Serialization:
>>> from dftscape.common import SerialisableDataClass
>>> @dataclass
... class MyData(SerialisableDataClass):
...     name: str
...     value: float
>>> data = MyData("test", 3.14)
>>> json_str = data.to_json()
>>> restored = MyData.from_json(json_str)
Component Registry:
>>> from dftscape.common import BaseRegistry
>>> class MyRegistry(BaseRegistry[MyComponent]):
...     pass
>>> @MyRegistry.register("my_comp")
... class MyComponent:
...     pass
>>> instance = MyRegistry.create("my_comp")
Distance Calculations:
>>> from dftscape.common import DistanceRegistry
>>> rmsd_func = DistanceRegistry.create("rmsd")
>>> distance = rmsd_func(xyz1, xyz2, method="kabsch")

Architecture Notes:

The common package follows several design principles:

  • Extensibility through registry patterns
  • Type safety with generic types and protocols
  • Serialization compatibility for distributed computing
  • Performance optimization for molecular structure operations
  • Clean separation of concerns between data, algorithms, and infrastructure

All components are designed to be thread-safe for read operations and support the distributed computing requirements of DFTScape's molecular landscape exploration workflows.

 53    allowing different types of components to be managed independently.

 56    provides methods for instantiation, lookup, and discovery. It's designed
 57    to be extended by specialized registries that add domain-specific
 58    functionality.
 59
 60    Key Features:
 61        - Generic type support for type-safe component management
 62        - Automatic per-subclass registry isolation
 63        - Decorator-based registration syntax
 64        - Runtime component instantiation with error handling
 65        - Component discovery and listing capabilities
 66

 68        >>> class MyRegistry(BaseRegistry[MyComponent]):
 69        ...     @classmethod
 70        ...     def create_special(cls, name: str, **kwargs) -> MyComponent:

 94    def register(cls, name: str) -> Callable[[Type[T]], Type[T]]:
 95        """
 96        Decorator to register a component class with a name.
 97
 98        This class method returns a decorator that registers a component class
 99        in the registry under the specified name. The decorator preserves the
100        original class while adding it to the registry for later instantiation.
101
102        Args:
103            name: The name to register the component under. This name will be
104                 used to create instances via the create() method.
105
106        Returns:
107            A decorator function that registers the component class and returns
108            the original class unchanged.
109
110        Raises:
111            ValueError: If a component with the same name is already registered.
112
113        Examples:
114            >>> @MyRegistry.register("my_component")
115            ... class MyComponent:
116            ...     def __init__(self, value: int):
117            ...         self.value = value
118            >>>
119            >>> # Later create instances by name
120            >>> instance = MyRegistry.create("my_component", value=42)
121
122        Notes:
123            - Registration typically happens at import time
124            - The decorator returns the original class unchanged
125            - Names should be unique within each registry subclass
126            - Registered classes can be instantiated with arbitrary arguments
127        """

129        def decorator(component_class: Type[T]) -> Type[T]:
130            cls._registry[name] = component_class
131            return component_class

142        but can also be used directly when you need the class rather than an instance.

161

163            - This method returns the class, not an instance
164            - Use create() for most use cases that need instances
165            - Error messages include all available names for debugging
166            - Case-sensitive name matching
167        """

170            raise ValueError(f"Unknown {cls.__name__} '{name}'. Available: {available}")

208            - Supports arbitrary constructor signatures
209            - Error messages include available component names
210            - Most common way to instantiate registered components

 46class SerialisableDataClass:
 47    """
 48    Base class for dataclasses with automatic JSON serialization support.
 49
 50    This abstract base class provides comprehensive serialization capabilities
 51    for dataclasses used in DFTScape. It automatically handles conversion to/from
 52    dictionary representations suitable for JSON serialization, with special
 53    support for numpy arrays, nested objects, and complex data structures.
 54
 55    The class uses Python's dataclass decorator and is frozen to ensure
 56    immutability, which is important for maintaining data integrity in
 57    distributed computing environments.
 58
 59    Key Features:
 60    - Automatic field serialization with type preservation
 61    - Numpy array handling with dtype information
 62    - Recursive serialization of nested SerialisableDataClass objects
 63    - Dynamic deserialization with class reconstruction
 64    - JSON string conversion methods
 65
 66    Usage:
 67        >>> @dataclass
 68        ... class MyPoint(SerialisableDataClass):
 69        ...     x: float
 70        ...     y: float
 71        ...     coords: np.ndarray
 72        >>>
 73        >>> point = MyPoint(1.0, 2.0, np.array([1.0, 2.0]))
 74        >>> config = point.to_config()
 75        >>> restored = MyPoint.from_config(config)
 76
 77    Notes:
 78        - Subclasses must be decorated with @dataclass
 79        - Frozen=True ensures immutability for thread safety
 80        - None values are skipped during serialization
 81        - Class and module information is embedded for deserialization
 82    """
 83
 84    def to_config(self) -> Dict[str, Any]:
 85        """
 86        Convert dataclass instance to dictionary representation for JSON serialization.
 87
 88        This method recursively traverses all fields of the dataclass and converts
 89        them to a dictionary format suitable for JSON serialization. It handles
 90        various data types including numpy arrays, nested objects, and collections.
 91
 92        Returns:
 93            Dict[str, Any]: Dictionary containing all serializable field values
 94                           with special handling for complex types.
 95
 96        Notes:
 97            - Numpy arrays are converted to lists with dtype information preserved
 98            - Nested SerialisableDataClass objects are recursively serialized
 99            - None values are skipped to keep JSON clean
100            - Class and module information is added for deserialization
101            - Handles lists, tuples, and dictionaries containing serializable objects
102
103        Examples:
104            >>> @dataclass
105            ... class Point(SerialisableDataClass):
106            ...     x: float
107            ...     y: float
108            >>> p = Point(1.0, 2.0)
109            >>> p.to_config()
110            {'x': 1.0, 'y': 2.0, '_class': 'Point', '_module': '...'}
111
112            >>> @dataclass
113            ... class Data(SerialisableDataClass):
114            ...     array: np.ndarray
115            >>> d = Data(np.array([1, 2, 3]))
116            >>> d.to_config()
117            {'array': [1, 2, 3], 'array_dtype': '<i8', '_class': 'Data', ...}
118        """
119        config = {}
120
121        for field_name, field_value in self.__dict__.items():
122            if field_value is None:
123                continue  # Skip None values
124            elif isinstance(field_value, np.ndarray):
125                # Convert numpy array to list and store dtype info
126                config[field_name] = field_value.tolist()
127                config[f"{field_name}_dtype"] = str(field_value.dtype)
128            elif isinstance(field_value, (np.integer, np.floating)):
129                # Convert numpy scalars to Python types
130                config[field_name] = field_value.item()
131            elif isinstance(field_value, SerialisableDataClass):
132                # Recursively serialize nested SerialisableDataClass objects
133                config[field_name] = field_value.to_config()
134            elif isinstance(field_value, list):
135                # Handle lists that might contain SerialisableDataClass objects
136                config[field_name] = []
137                for item in field_value:
138                    if isinstance(item, SerialisableDataClass):
139                        config[field_name].append(item.to_config())
140                    elif isinstance(item, tuple):
141                        # Handle tuples that might contain SerialisableDataClass objects
142                        config[field_name].append(
143                            tuple(
144                                (
145                                    subitem.to_config()
146                                    if isinstance(subitem, SerialisableDataClass)
147                                    else subitem
148                                )
149                                for subitem in item

1945def _no_init_or_replace_init(self, *args, **kwargs):
1946    cls = type(self)
1947
1948    if cls._is_protocol:
1949        raise TypeError('Protocols cannot be instantiated')
1950
1951    # Already using a custom `__init__`. No need to calculate correct
1952    # `__init__` to call. This can lead to RecursionError. See bpo-45121.
1953    if cls.__init__ is not _no_init_or_replace_init:
1954        return
1955
1956    # Initially, `__init__` of a protocol subclass is set to `_no_init_or_replace_init`.
1957    # The first instantiation of the subclass will call `_no_init_or_replace_init` which
1958    # searches for a proper new `__init__` in the MRO. The new `__init__`
1959    # replaces the subclass' old `__init__` (ie `_no_init_or_replace_init`). Subsequent
1960    # instantiation of the protocol subclass will thus use the new
1961    # `__init__` and no longer call `_no_init_or_replace_init`.
1962    for base in cls.__mro__:
1963        init = base.__dict__.get('__init__', _no_init_or_replace_init)
1964        if init is not _no_init_or_replace_init:
1965            cls.__init__ = init
1966            break
1967    else:
1968        # should not happen
1969        cls.__init__ = object.__init__
1970
1971    cls.__init__(self, *args, **kwargs)
